💡 実施内容 (What):
- `AnalysisResult` インターフェースに `_uri` プロパティを追加しました。
- `InterventionManager.generateIssueId` において、文字列補間によるID生成結果を `result._id` にメモ化し、キャッシュキーとして `result._uri` を用いて documentUri が一致するか検証するよう修正しました。

🎯 理由・目的 (Why):
- `generateIssueId` はイベントハンドラ内で高頻度に呼び出されるため、毎回の文字列生成が無駄なメモリアロケーションとGCを誘発し、パフォーマンス低下の原因となっていました。
- 以前のコードレビューで指摘された通り、`documentUri` が異なるケースで古いキャッシュが返る（stale cache）不具合を防ぐため、URIの一致チェックを追加しました。
- TypeScriptの型定義エラーを避けるため、`AnalysisResult` に `_uri` プロパティを明示的に追加しました。

📊 影響 (Impact):
- 100万回実行時のベンチマークで、実行時間を約 46ms から約 9ms へと大幅に削減（約80%減）しました。これにより、イベントループのブロッキングが軽減され、VS Code エディタの応答性が向上します。

🔬 検証方法 (Measurement):
- 変更前後の `generateIssueId` 呼び出しループの実行時間を `performance.now()` で計測しました。
- `npm run lint:fix && xvfb-run -a npm test` がすべてパスすることを確認しました。
