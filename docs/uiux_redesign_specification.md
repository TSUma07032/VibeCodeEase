# vibeCodeEase: UI/UX リデザインおよびアーキテクチャ要件定義・仕様書

## 1. プロジェクトの目的とターゲットユーザー
- **目的:** ユーザーの学習支援、自力での設計力向上、細かいミスの裏でのフォロー。AIに「手っ取り早くコードを書かせる」ツールではなく、「AIとのペアプログラミングを通じた学習と成長」を提供する。
- **ターゲット:** 自分で考えながら良い設計を学びたいエンジニア、主体的にコーディングを行いつつ、細かいミスや設計のブラッシュアップだけを裏でAIに拾ってほしいエンジニア。

## 2. コアコンセプト: AIワークスペースの可視化
- **非侵入型の学習体験:** ユーザーの手元のエディタには直接干渉しない。AIは裏の仮想的な「AIワークスペース」で継続的にコードをブラッシュアップする。
- **2つのワークスペース:**
  - **ユーザーワークスペース (手元エディタ):** ユーザーが主体となって作業を行う通常のVS Codeエディタ。
  - **AIワークスペース (サイドバー / 専用パネル):** AIがユーザーのコードをベースにブラッシュアップを行った「AI版のコード」を保持・表示する領域。

## 3. インタラクションとデータフロー
本システムは以下の3つの主要なインタラクションサイクルで構成される。

1. **ユーザー To ユーザー (手元での作業)**
   - ユーザーはAIの処理待ちなどのブロックを受けることなく、シームレスに手元でのコーディングを継続する。
2. **ユーザー To AIワークスペース (即時反映)**
   - **トリガー:** ユーザーの手元での「ファイルセーブ」等の明示的アクション。
   - **処理:** セーブされた最新のコード状態が、即座にAIワークスペースのベース状態として同期される。
3. **AI To AIワークスペース (非同期の自己改善)**
   - **トリガー:** 定期的なインターバル（設定で変更可能）やバックグラウンドサービス(`llmBackgroundService`等)によるポーリング。
   - **処理:** AIがAIワークスペース上のコードを継続的に解析・改善し、自律的にブラッシュアップし続ける。

## 4. UI / UX 仕様 (GitHub風Diffレイアウト)
- **メインレイアウト:**
  - エディタ領域（左）：ユーザーが作業している手元のコード。
  - サイドバーまたは専用パネル（右）：**AI版のコードのみ**が表示される。
- **差分表示と学習支援コメント:**
  - AI版のコードUI上では、ユーザーの手元のコードと「差分がある行」がハイライト（色付け）されて表示される。
  - 差分行（AIの提案行）にはインタラクション（クリック等）が設定されており、クリックすると「AIによる変更理由」「設計上の改善ポイント」「ミスの解説」などの指摘リストがポップオーバーやインラインコメントとして表示される。
- **ユースケース:**
  - ユーザーは手元で一通り作業を終えた後、「ふと」AIワークスペースの画面を見る。
  - そこにはブラッシュアップされたコードと、どこが悪かったのかの指摘リストが一覧化されており、ユーザーはそれを読んで学び、手元のコードを改善する（あるいはワンクリックで取り込む）。

## 5. 実装に向けた技術的アプローチ
- **既存基盤の活用:** `src/core/llmBackgroundService.ts` にあるスロットリング付きポーリングや、既存の `DiffProvider` の仮想スキーム（`${DIFF_SCHEME}://modified...`）など、バックグラウンド解析の仕組みをベースにする。
- **UIの再構築:** 
  - 現在のVS Code標準のDiffビューを拡張するか、Webview内でMonaco Editor等を利用し、「AI版のみを表示し、差分箇所にデコレーションとコメントを付与する」UIを実装する。
  - Webviewの場合は、React側にDiff結果とコメント情報を渡し、GitHubのPRレビュー画面のようなリッチな体験を提供する。
